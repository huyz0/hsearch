# Core-v1 reference fixture inventory

Status: **local work in progress**. An exploratory pinned-reference run passed thirteen searches and four analyzer expectations; see `docs/plan/evidence/m02-01-reference-experiment.md`. Portable/native controller qualification remains pending. No client or hsearch conformance has run, and there is no hsearch HTTP/search service. Integrity checks cannot close M02.01 or establish client compatibility.

The original public toy dataset has eleven explicitly identified documents, an explicit strict schema and a named standard-analyzer configuration. Fourteen search requests have manually enumerated document/count/sort/ranking oracles; four analyzer inputs have token, position and UTF-16 offset expectations. Eleven mutation histories contain34steps for CRUD, create conflicts, strict schemas, mixed/repeated-ID/malformed-tail bulk, generated-ID adaptation, stale OCC, forced refresh, PIT pages under mutation and truthful count relations. Sixteen native-property inputs and fourteen unsupported request examples are separate future hsearch conformance inputs, not executed reference requests. File and profile hashes are in `manifest.json`. The tenant field is sample data, not an authorization proof. Scores are not compared bit for bit, and this small corpus is not a workload or scale result.

Reference candidates are [OpenSearch 3.9.0](https://github.com/opensearch-project/OpenSearch/releases/tag/3.9.0), revision `4ee42a94e87f66fbf1e62a9871b1b87f91e02472`, and [opensearch-py 3.2.0](https://github.com/opensearch-project/opensearch-py/releases/tag/v3.2.0), revision `8991792d3fcdfc221c9aef62d7e82c3d15ff0206`. Their official registry image index and native architecture digests were inspected. The exact x86_64 image was pulled and executed in the isolated exploratory run; ARM64 execution remains pending. Upstream's [client compatibility statement](https://github.com/opensearch-project/opensearch-py/blob/8991792d3fcdfc221c9aef62d7e82c3d15ff0206/COMPATIBILITY.md) does not establish hsearch compatibility. No dependency source, binary or copied server response is vendored.

Run `python tools/api_fixtures.py` for bounded file/hash/profile/schema/identity checks. Its output reports reference execution and hsearch conformance as NOT-ASSESSED; static integrity is separate from execution evidence. Negative controls reject dataset tampering, stale profile identity, invented execution and unknown inventory paths. This tool is an inventory checker, not a search implementation or reference executor.

Current inputs and adaptation reports cover all sixteen [profile areas](../../../docs/plan/api-compatibility.md). The new ranking/mutation histories still need reference execution, final controller qualification and independent review. Native receipt/OCC/visibility/pagination/admission properties and unsupported examples remain future hsearch execution, with no served wire ABI frozen here. The finite aggregation cases are reference baselines for bounded native semantics; they do not promise universal aggregation DSL support. The analyzer is a candidate reference configuration and does not freeze hsearch's eventual analyzer profile or prove engine equivalence.

Final portable/native reference execution must produce actual independent observations before the corpus is described as qualified goldens. Native adapter/service conformance remains a later gate. The pinned user OpenSearch fork/serverless request tests are available and selectively inspected in `docs/plan/research/api-adaptation-inventory.md`. Current application-specific client/proxy configuration and representative private traces/datasets have not been supplied or identified; missing fixtures stay explicit and no universal migration claim is made.

Run the portable component check with `python tools/reference.py --state-root /tmp/hsearch-dev-leases --evidence-parent /tmp/hsearch-api-reference`. It refuses dirty/hidden source inputs, supports a detached CI checkout without granting task ownership, and freezes bounded validated inputs in memory. It contacts only its own pinned network-none container through loopback Docker exec; no external service URL is accepted. The node is non-root with hard CPU/memory/PID/no-swap limits, bounded Java scratch/data tmpfs, bounded lifetime/logs/observations and sampled backend disk/reserve monitoring. Actual cgroup and mount evidence is recorded. This isolated reference disables its Security plugin; it is not hsearch security or deployment qualification.

A failing run preserves its exact stopped owned container and lease when diagnostic evidence is needed. After inspecting the emitted evidence and the worker has exited, invoke the same tool with `cleanup` and its exact emitted namespace. Cleanup verifies source/engine, departed owner, known CID/image/labels, terminal state and captured evidence; live, unknown or foreign state stays preserved. It never force-removes resources or deletes source files.

Hosted sandbox qualification runs this controller on both native architectures. Only the dedicated public reference evidence directory is uploaded, with a three-day retention; the shared lease/snapshot directory contains TLS keys and is never included. The pinned [upload-artifact7.0.2 action](https://github.com/actions/upload-artifact/tree/cf430e030ddbb5b0abf93d22962f4752f3646cd9) uses node24 and declares [MIT](https://github.com/actions/upload-artifact/blob/cf430e030ddbb5b0abf93d22962f4752f3646cd9/LICENSE). No third-party source/binary is vendored or released.
