# Opaque image component v1

This is an M01.20 source candidate. It represents only the exact failed pair named in the accepted M01.18 design: 84 nodes, 69 files and 224852 payload bytes, including both roots and every parent. It does not qualify the old failed job, M01.08, M01.17 or a live retention operation. Native x64/ARM, applicable production coverage, independent final-source review, full CI and protected integration remain required. No actual FFF bytes are used by the component tests.

`plan(manifest, expected_pin, original, physical)` consumes canonical `hsearch-opaque-input-v1` bytes and a caller-supplied SHA256. Its exact fields are `schema`, integer `version=1`, fixed historical `history`, and sorted `entries`. Every entry has `path`, `kind`, `mode`, `uid`, `gid`, `mtime_ns`, `windows_attributes`, `nlink`, `bytes` and `sha256`. Unsupported USTAR fields, aliases, links, reparse points, missing parents, extra fields and changed denominators refuse. The metadata and history remain lossless in the embedded index; USTAR headers carry integer-second mtime while the index preserves nanoseconds. The hash is an identity commitment, not authentication of the manifest or its source.

The deterministic format is sorted USTAR members followed by the reserved `__hsearch_opaque_image_v1__/index.json` member and zero padding to a 10240-byte record boundary, with at least two terminating zero blocks. The canonical index binds every original entry, original failed history, manifest SHA256 and full caller-held M01.19 `Original` context. The format is versioned separately from the frozen M17 representation; it does not claim byte compatibility with that unaccepted format. Verification compares exact generated headers, original payload hashes, every index byte, padding, declared length, EOF and the externally pinned whole-image hash. No extraction occurs.

`Operation(plan, session)` requires an actual accepted M01.19 `Session` with the same original-context pin. It never constructs a clock, store or allowance. `build(source, destination)` uses already admitted source/destination ports; `open(port, expected_pack_sha256)` verifies an existing image. An operation can enter build/open once. Each call is serialized against reentrant/concurrent use. M01.21 must provide exclusive session ownership across operation objects and processes.

Source ports supply exact recorded metadata and distinct opaque descriptor identities, bounded byte reads and EOF. Destination ports supply exclusive empty-object admission, stable object identity, content revisions, append acknowledgments, bounded reads and durable sync acknowledgments. The integration must prove these properties for real descriptors and the declared host profile. Python Protocol conformance does not authenticate them. This component implements no host adapters, raw-root enumeration, source/task/owner/approval checks, leases, transport, mapping publication or retirement. It neither imports the frozen M17 controller nor delegates effects to it.

Construction refuses a nonempty destination or source/destination identity alias before writing. Every payload is independently hashed and probed at EOF; source metadata/identity is checked before and after reading and again after sync. Final verification reads back the entire image after acknowledged sync. Partial writes, wrong counts/types, changed identities/revisions, late completion, uncertain acknowledgments and corrupt readback poison the operation and deny the original shared Session. There is no truncate, removal, retry, clock refresh, credit refund or guessed completion. A port exception is redacted to a fixed reason; an original-context refusal remains the primary failure. Actual durability, source stability and crash recovery are host/integration obligations, not facts inferred from a mock callback returning `True`.

The returned `View` exposes immutable original entries and bounded opaque member ranges. Each range rehashes the complete original member before returning at most 65536 bytes, including a zero-length request. Changed image stamps refuse. These bytes cannot be requested through a semantic Reader or qualification-export API. Evidence explicitly carries `opaque_only=True` and `qualification=False`; it proves representation consistency under admitted ports, not authority or task acceptance.

`composite(plan, physical, present_paths)` retains the original opaque logical accounting during partial retirement. It validates the actual subset and derives its bytes from the pinned inventory. It performs no removal. Planning checks normal staging occupancy and final occupancy plus the unchanged 42-node qualification reserve. The original 4096-node/64MiB archive, 2MiB pack and 1MiB index limits are conjunctive; no maintenance exception or additional pool is created.

Every port action has M01.19 original-clock checks before and after it. Metadata/descriptor calls conservatively debit 131072 audit bytes; read/write requests debit their requested lengths before use, including failed calls and one-byte EOF probes. Construction predebits four rescans for all source metadata/identity passes, even if it fails early. Full-image verification and each member-range rehash debit another original rescan; successful construction consumes five. These use the existing 256MiB/32-rescan durable aggregate credits. Raw pipe credits are untouched. Remaining context/authority/transport/public diagnostics and archive metadata pools, real port lifetimes and exact owned-handle cleanup remain M01.21 obligations under the unchanged bridge.

A conservative complete-build bound uses at most 274 emitted chunks and 274 verified chunks: 85 headers, at most 72 payload chunks, 69 member paddings, 16 index chunks and 32 tail chunks. There are 336 source metadata calls, one initial destination description, 548 write descriptions and 550 verification descriptions: at most 1435 metadata/description calls. Thus complete construction plus mandatory readback debits at most `1435*131072 + 224852 + 69 + 2*2097152 + 1 = 192507546` audit bytes. This is within the existing 268435456-byte limit and leaves no new allowance. Actual native latency or hidden kernel work is not bounded by that logical debit. A later consumer remains subject to the same original credits and rescan cap; it cannot assume unlimited ranges or recover a fresh budget.

Owned memory is bounded by the accepted 1MiB codec/object limits (depth24, 50000 visits), the retained manifest/index of at most 1MiB each and 84 immutable entries. Construction streams chunks of at most65536 bytes; a consumer can temporarily hold one such chunk, collected slices totaling at most65536 bytes and their joined result of at most65536 bytes. USTAR headers are fixed512 bytes. Parsed JSON and encoder bookkeeping remain within the accepted codec's bounded graph; these structural bounds are not a measured Python RSS certificate. Caller/adapter allocation, descriptor behavior and actual native buffers need their own admitted proof; this module does not attest arbitrary callback implementations. Error reasons are constant strings and no payload/path is logged.
