M01.19 implementation candidate. This component supplies a typed original clock proof, conservative aggregate credits, strict codec and conditional Linux FD cursor. It has no task, artifact, image, approval, transport or deletion authority. M01.17 remains frozen and unaccepted at hard3. Acceptance of this candidate still requires the declared native evidence, final-source checks, independent reviews and CI. No deployed host authority is bundled.

## Original proof and durable port

`Original.begin(operation, source, request, clock, duration_ns)` captures three original integer starts and endpoints. Duration is positive and at most1,200,000ms. The versioned API and units are explicit. `Session.publish` creates exactly one original proof through `Store.compare_exchange(None, raw)`. Before the consuming integration's first effect, it must retain the acknowledged original proof pin and bind it to the operation/source/request and admitted host profile. `Session(store, clock, expected_pin)` restores that exact proof. It never derives a deadline from wall slack or creates a replacement admission.

The trusted `Clock` port supplies attested samples. Validation requires identical boot/domain/profile/evidence, no regression against the retained high-water sample, and all three ticks strictly below the original endpoints. Equality expires. BOOTTIME charges suspend if its adapter/profile is actually qualified. Wall time can shorten validity, never extend the original endpoints. Before/after storage bookends catch late CAS returns; expiry and known failures set a durable terminal denial when the Store can acknowledge it. A poisoned handle never resumes. Each stored high-water is the sampled pre-CAS ceiling; the subsequent validity sample is not a claim that every unobserved wall jump was detected.

The integration supplies an exclusive, bounded, antirollback Store. `Receipt(raw, acknowledged)` means durable acknowledged identity, not bytes merely visible after a write. `compare_exchange` must atomically compare exact previous bytes and bind the same original proof; conflict or uncertain acknowledgment refuses. The integration must retain uncertainty across process death, reconcile an exact uncertain publication and reject stale/rebound state. A digest is not authentication. The component cannot prove these port obligations using caller-provided JSON. No production storage adapter, growing checkpoint log or new control-I/O pool is added. Its one bounded CAS record must fit the existing64MiB registry and the consuming integration's original metadata/control-I/O envelope.

`reserve` durably debits before I/O. Both pipes, EOF, errors, timeouts and unused reservations must use the same raw budget. Each raw debit is1..16bytes and consumes one of512 reservations, with8192bytes total. There is no refund or reset. Audit bytes remain256MiB, rescans32 and logical entries4096. The cursor charges every root traversal as a rescan, child directories share that traversal, and all next/EOF/overflow probes debit the same audit budget. These are conjunctive ceilings; conservative reservations can refuse before a logical maximum. The consumer must route every relevant read/transport/rescan through these ports, preserve the other bridge predicates and validate again before accepting effects or completion.

## Linux ports and their missing qualification

`LinuxClock` observes bounded boot/proc namespace information, interpreter, libc version, architecture and kernel, then asks an independent `DomainAuthority` to verify it. PID1 namespace visibility is optional observational data; PID1 equality is never treated as proof of the initial HOST time namespace. The authority must establish trustworthy proc provenance, the actual original host domain/lifetime and deployment no-rewind evidence. A namespace inode/device or boot ID alone is insufficient. Reboot, migration, unknown domains, snapshot/rewind uncertainty and missing evidence refuse. No wall-derived fallback exists. Windows is explicitly unsupported by the native adapter.

`CursorPool(session, authority, memory_bytes, fd_limit)` consumes held directory-FD capabilities, not arbitrary artifact paths. The integration owns root identity/authorization and mutation exclusion. `open(fd, cap=N)` opens an independent `openat(".")` description so `dup` cannot share directory offsets. The pool reserves the borrowed input FD, its owned FD and scandir's internal duplicate before opening. It reserves the qualified stream/native-buffer and worst-case entry/name representation before calling real `os.scandir(fd)` or advancing. No Path.iterdir/list wrapper is used. `next` bookends the OS call, refuses an N+1 overflow before retaining/statting it, and charges one EOF probe even for an empty directory. Entries use no-follow FD-relative stat; children use no-follow directory open plus identity comparison. Depth24, active stream/FD/memory limits and operation-wide entries/audit/rescan debt apply across nesting and recovery. Closing releases live capacity, never cumulative credits. Unknown close outcomes retain capacity and poison the pool/context. Supplied FDs outside this component remain the integrator's bounded responsibility.

The independent `CursorAuthority` must bind the observed interpreter/libc build, filesystem/mount/name bound and exact source to finite reservations for stream allocation, worst-case names/objects and hidden native work per step. A glibc2.36 source candidate clamps its directory buffer to1MiB; this code requires at least1MiB+64KiB stream reservation, but that number is not deployed-build attestation. `PC_NAME_MAX` is checked against the proved name bound; unknown/unsupported profiles refuse. Native buffering and hidden readdir/refill work are separate. Python safe APIs provide no arbitrary-kernel syscall latency bound, filesystem snapshot or rollback of a late effect. These remain explicit unmet predicates until the actual declared deployment supplies the required proof and same-original-budget supervision. Numeric proof fields alone do not qualify an environment.

## Codec and validation

Canonical UTF-8 JSON is bounded to1MiB. Lexical containers are checked at depth24 before decoding; rooted object/key/value visits separately retain depth24 and50000nodes. Strings, integer width/range, duplicate keys, unknown schema fields, malformed UTF-8, noncanonical forms and floats are rejected. The review envelope's separate depth32 is not imported.
