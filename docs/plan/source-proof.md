# Immutable source proof component

M01.11 implements the source-only boundary from the [accepted redesign](coverage-redesign.md). This candidate awaits independent review/native qualification. It cannot issue a coverage score, run a compiler/test, merge profiles or control Docker. M01.12 must consume and recheck this interface while independently reviewing the entire retained collector and every inherited control. Original M01.07 remains blocked at its hard third round; none of its failed reports/counters were reset.

`tools/coverage_sources.py` exposes `prove(root, head=..., base=..., sources=..., deleted=..., limits=...)` and `verify(proof, root, ...)`. `sources` is the trusted coordinator's complete selected production-source manifest: relative POSIX path to `{owner, sha256, line_count}`. Inventory completeness, production ownership, frozen checkout lifecycle and qualified event/base selection remain caller responsibilities. The primitive verifies actual byte hashes/physical line counts and performs two source bookends, but these observations are not a filesystem lock against mutation after observation. Deleted paths are explicit and have no executable head lines. The versioned `tools/coverage-source-proof.schema.json` documents the evidence shape; recomputation rejects missing/extra/stale/corrupt fields and line results. External loaders must enforce byte/depth/duplicate-key bounds before constructing a proof object; M01.12 retains the existing bounded artifact reader.

The repository binding hashes the unredirected absolute root/common Git-directory identities. It is a local coordinator identity, not a remote URL or user authentication proof. Both commits are exact40 hex SHA-1 identities; SHA-256 Git repositories explicitly refuse in v1. The actual HEAD must match at both ends. Ancestry is traversed through independently hash-checked raw commit objects, not a mutable display/commit-graph view. A base must be an actual ancestor; an absent base is valid only for a proven parentless root. Shallow files, grafts, alternates and replace refs refuse. Redirecting Git environment refuses; other inherited Git display/config variables are removed. No `git diff`, filters, textconv or external diff tool is invoked.

The implementation strengthens the proposed NUL-framed tree inventory by parsing Git's raw tree-object NUL records directly and independently hashing each raw tree. Tree modes/UTF-8 names/object widths/duplicates/counts are checked. Only regular selected source files qualify; submodule/symlink sources refuse. Valid Unicode/spaces are supported. C0/DEL control characters, backslashes, colons, dot/traversal/reserved Git path components and invalid encodings explicitly refuse rather than being reinterpreted. A rename is an explicit deletion/new path in v1. Blob sizes are preflighted and bounded pipes read raw bytes; independent Git object hashes bind those bytes.

Physical lines end only at byte LF. A terminated line includes LF in equality comparisons, so CRLF and final-LF changes are explicit. Empty bytes mean zero lines; a final LF does not invent an empty trailing line. U+0085/U+2028/U+2029/CR/VT/FF remain content. The deterministic `byte-lf-myers-delete-tie-prefix-v1` algorithm removes an equal prefix, uses minimal Myers alignment, prefers deletion on equal predecessor frontiers and returns inserted/replaced head line numbers. No semantic change or Git-display-hunk equality is claimed. Repeated-line ambiguity is pinned by the algorithm version/tie rule and manual cases. An independent dynamic-programming LCS oracle checks optimality and subsequence reconstruction over exhaustive small lines and500 fixed-seed original byte cases.

Default maxima are10,000 tree/selected paths,64 MiB/blob,256 MiB combined blob inputs,2 million physical line entries,8 million comparison/frontier/backtrack steps,250,000 retained frontier cells,8 MiB aggregate commit/tree object metadata,4 MiB serialized proof and60 seconds for the whole successful proof. Ancestry visits at most10,000 commits/64 parents per commit. Each child command has16 KiB argument/64 KiB stderr limits and the remaining whole-proof deadline. Concurrent draining bounds capture; failure kills/reaps only the owned non-shell Git child. Cleanup has a finite additional wait and cannot convert failure into success. Blob object-byte checks happen before allocation; line/algorithm/proof checks refuse on exhaustion. These are finite bounds rather than a promise to complete every input below the raw byte cap: repetitive changes can legitimately hit the stricter frontier/work bound. Lower test profiles are permitted; raising ceilings needs review and measurement.

Run `python -m unittest tools.tests.test_coverage_sources` or the full owned Linux sandbox. Controls include exact Unicode false-pass source/mode inventory, fake raw-string headers, binary diff attributes, inherited context/external diff, spaces/Unicode names, creation/deletion/empty/final-newline/mode-only cases, manual repeated-line choices, DP/fuzz oracles, wrong/stale/missing/nonancestor bases, corrupt object bytes, source mutation bookends, redirect/shallow/replace views and forced byte/line/work/frontier/output/deadline failures. Native qualification must record actual cost and the original failed-parser replay beside the new attribution. No test changes the original oracle values or clears the old gate.

The retained public fixture and local replay preserve that result. Exact mode-only B now means zero added lines; the earlier whole-file approximation is intentionally retired, with this explicit migration subject to independent review. Unknown-base all-source dilution remains forbidden. M01.09's original ARM cause and M01.08 remain open; no collector/runtime/service/release acceptance follows from source-proof tests.
