## Immutable source-proof contract

M01.11 will read exact base/head commit and blob identities through Git's object interface. NUL-framed tree records identify regular tracked source files; raw blob bytes are independently checked against their object IDs. Redirecting Git environment and mutable replace/graft views cannot qualify ancestry or object identity; unsupported/shallow evidence refuses rather than changing the baseline. It will not parse `git diff`, invoke textconv/clean/smudge helpers, or use display-oriented quoting/prefixes/attributes to infer line identity. [Git documents raw object access](https://git-scm.com/docs/git-cat-file) and [NUL-framed tree output](https://git-scm.com/docs/git-ls-tree).

Inputs bind the repository identity, actual head, qualified base, selected production source paths, source hashes/physical line counts, algorithm version and resource profile. Head blob bytes must match the frozen actual source manifest. Base files absent in the base tree are new; a missing required head blob is an error. Deleted sources are recorded explicitly when requested but cannot invent executable head lines. Mode-only changes with identical blob bytes have zero added lines. Renamed paths use explicit delete/new-path semantics in v1. Paths with spaces and valid Unicode are supported through NUL framing; unsupported path encodings/control bytes fail explicitly.

Line framing is byte LF only. CR bytes, UTF-8 U+0085/U+2028/U+2029, vertical tabs and form feeds remain content, so raw-string data cannot create protocol records. A final LF terminates its physical line without creating an extra empty line; an empty blob has zero physical lines. CRLF is preserved in byte comparisons. Source/profile normalization is never inferred from a display-oriented patch.

The versioned delta algorithm will use deterministic bounded Myers alignment over byte-LF lines, with deletion preferred when predecessor frontiers tie, plus independent small dynamic-programming/reference checks. It reports added/replaced head-line indices, not semantic coverage of unchanged text. Equal/mode-only blobs produce no added lines; a proven new file reports every physical head line. Minimal alignments can be ambiguous on repeated lines, so the version and tie rule are part of the proof and manual cases freeze expected choices. No claim of identical Git display-hunk choices is required.

The initial implementation profile must enforce finite limits before allocation: at most 10,000 paths, 64 MiB per blob, 256 MiB combined old/new input, two million physical line entries, bounded command arguments/metadata/output, a whole-proof deadline and bounded algorithm comparison/frontier storage. Proposed working limits are eight million line/comparison operations, 250,000 stored frontier cells, 4 MiB serialized proof, and 60 seconds total, with each Git child limited by the remaining deadline. Implementation may choose stricter measured limits before acceptance; it cannot silently discard a path or return a success on exhaustion. Capture/drain subprocess output while enforcing byte bounds, preserve primary failures, and stop only owned processes. Native qualification must exercise real limits and record actual cost, not merely assert configured numbers.

The proof records base/head/path/blob/source bindings, algorithm/profile versions and exact head-line results. Merge recomputes or independently verifies the proof against actual immutable inputs and current frozen source. A stale/corrupt/truncated proof or changed source refuses. This is content-bound trusted-coordinator evidence, not authentication against a coordinator able to forge its own inputs.

## Base and fallback policy

An unknown base cannot establish a changed-line percentage. Counting every source line as changed can dilute an uncovered new line with covered old lines, so it must not substitute for an unknown patch. A normal run requires an exact ancestor commit; an explicit empty baseline is allowed only for an actually proven parentless root commit. Missing/non-ancestor bases fail changed-line qualification with an actionable diagnostic.

The impact planner still selects the complete safe suite when classification/base evidence is unavailable. That selection does not waive source-proof qualification. M01.12 must wire explicit valid bases for PR/main/manual events, preserve checkout history and test each event mode. Manual/fallback runs must supply a qualified base rather than silently passing an all-production approximation. Strict branch protection, actual selected jobs and expected-head merge guards remain separate requirements.
