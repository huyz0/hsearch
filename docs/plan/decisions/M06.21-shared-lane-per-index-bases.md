# Decision M06.21: a shared lane with per-index bases

ID M06.21, 24 November 2026, status **proposed (revised after independent review)**, owner role storage/runtime.

Question and affected requirements: the node serves each index on its own lane today (M06.19), so every acknowledged write is its own lane slot and a node's write requests grow with its active indexes. M03.09 accepted shared lanes for indexes of one policy. What does the store layer need so several indexes write one lane and each still publishes and recovers from its own base? Affects PR-01 (10M indexes), PR-11 (requests scale with nodes and bytes), PR-06 (no lost acknowledged write) and the one-write-log-per-node rule.

Observed implementation and limits (read from the tree, not measured):

- The lane layer already supports sharing: `members.rs` (`shared_group`, `join_members`), `sealing.rs` (a seal names an index's last sequence in a lane), `promote.rs` (`route` returns `Shared`, `Promoted` or `Unrouted`), records carry the index identity, and recovery filters a lane's slots by `target.index`.
- The store layer assumes one index per lane: `StructuralHead.checkpoint` names one manifest root and `cover` one slot ordinal for the whole lane; `recover.rs` reads `head.checkpoint` as the index's base and starts replay at `base.covered` with `head.cover` as the first slot; `Publisher::activate/replace` move that checkpoint; compaction and collection read it (`compact.rs`, `gc`).
- `Serving` owns its `Committer<LaneWriter>` and its per-index sequence (`next_seq`), so two hosts cannot share one lane writer.
- Readers of `head.checkpoint` as a real manifest root, all of which a shared lane must stop using: `rebuild.rs` (host open, `verify_root`), `recover.rs`, `sweep.rs` (live root for collection), `snapshot.rs` (`live_root` for pins), `compact.rs` (`validate_source`, `finish`), and `served.rs` (the head read that decides "never created").
- Requests today: one conditional create per lane slot, one head CAS per structural transition (never per append).

Concrete alternatives:

- **A, keep a lane per index.** No design work; every active index pays one slot per commit window and the node holds a fenced writer per index. Rejected by M03.09 on cost and retained objects.
- **B, one base for the whole lane** (the head's checkpoint names a lane-wide base). A lane base would hold every member's documents: it is not an index's base, cannot be opened per index, and a 1,000-member lane rewrites everything to advance one index.
- **C, per-index conditional base pointer and a lane cover that is a lower bound over members** (below).

## Decision

C. The checkpoint stays per index; the lane head's `cover` becomes what it always meant for a shared lane, the slot below which **no member needs a record**, advanced by the node from state it already holds.

1. **Per-index base pointer.** One conditional object per index and shard, `{layout}/…/{index}/{shard}/BASE`, written by compare-and-swap, holding: the index's manifest root (what `head.checkpoint` names today), the index's `covered` sequence, the **lane cover for this index** (the lowest lane ordinal that can hold a record of this index above `covered`, or the lane tail at publish time when none can), the lane it is on, and a sequence that rises by one per write (named so it is not confused with a manifest root's generation). Publishing a base is: write the immutable base objects (unchanged), then CAS the pointer. One CAS per base, as today's head transition is one CAS per base. **The pointer's successor rule** is a predicate the writer checks against the version it read before its CAS (the CAS then makes the check race-free): the covered sequence and the lane cover never fall, the pointer sequence rises by one, the lane is unchanged unless the index was promoted, and the lane cover is at or above the head's cover. A paused writer holds an old pointer version, so its CAS fails, and a writer that re-reads refuses a pointer it would lower; no acknowledged slot is reclaimed on the strength of a pointer that has been outrun.
2. **Recovery reads the pointer, not the head's checkpoint.** An index opens with one GET of its pointer (a missing pointer is a new index: replay from the start of its membership), verifies the root as today, then replays the lane from `max(pointer lane cover, head cover)` (an idle index's pointer cover may sit below slots a later reclaim removed, which held nothing of its), applying only records whose index and sequence continue the base. The seal and promotion follow (`route`) is unchanged. A lane whose head names a checkpoint (a dedicated lane written before this change) is read as before: the pointer is optional, so nothing is migrated.
3. **The lane head's cover is a lower bound the node maintains.** The head's cover advances (a `Checkpoint` transition with a witness root, see below, carrying the writer epoch it was computed under, so a node that lost the lane cannot raise it: its cover is at most its own tail, which is below its successor's fence) only to the minimum over the **pinned set**, the indexes that can still have an uncovered record on this lane:
   - **Resident hosts.** A host is pinned from its open until it has published a base covering everything it wrote, at the lowest lane ordinal of a record above its pointer's `covered` (before its first publish after a recovery, the position recovery started from, never the lane end). The cover a host reports comes from the shared committer's authoritative next ordinal, read before the base's cut.
   - **Eviction and failure never unpin.** A host leaves residency only by publishing a base that covers its writes; a host that is `Broken` stays pinned until it is recovered. Closing a host publishes.
   - **The tail set.** When the node opens a lane (seal on open) it scans from the head's cover to the tail and collects the member indexes with a record above their pointer's `covered` (a pointer read per such index, bounded by the tail). Each is opened, recovered and publishes a base before the open completes, then unpins. Indexes that are deleted (a seal and a removed membership) or sealed after a promotion are not in the set, except that a promoted index stays pinned on its **source** lane until a base on its new lane covers its seal sequence (covers are compared only when the pointer's lane equals this lane, since a successor lane's ordinals restart).
   - **Bounded unpublished span.** A resident host publishes a base once the lane span of its uncovered records exceeds a byte bound, checked on commit (event-driven, no timer), so a lightly written index cannot pin the lane indefinitely; the same bound applies to the tail scan, which is why it stays proportional to the tail's bytes.
   An index outside the pinned set published a base covering all it wrote: **an idle index never pins the lane and costs no request**. No step reads the pointer of every member, so requests do not scale with indexes.
4. **Witness root.** `Change::Checkpoint` needs a root identity. On a shared lane the head's checkpoint root is a witness derived from the lane id and the cover (`sha256("lane-cover" ‖ lane ‖ cover)`, truncated to an `Id`) with no object behind it, which satisfies `validate_successor` (a root rises with the cover). Every reader of `head.checkpoint` listed above reads the index's pointer instead when the index has one: host open (`rebuild.rs`), recovery, collection (`sweep.rs`, with the live root and its manifest generation from the pointer's root), snapshot pins (`snapshot.rs`), compaction (`compact.rs`: the source must be the pointer's root, and the replacement is one pointer CAS) and creation detection (`served.rs`). Collection of lane slots reads `head.cover`, as before.
5. **Shared committer.** One thread per lane owns the `Committer`. Hosts submit their prepared records (the index id, the index's sequence, the mutations) over a bounded channel; the thread packs records of many indexes into one lane slot up to the slot bounds, writes it, and returns each record its outcome (`Committed(ordinal)`, `Rejected`, `Unknown`), in order. A fence loss or poison is the lane's: every host of the lane is `Broken` and reopens, exactly as a lone host does. `Serving` takes the log through a trait with `commit`, `commit_external` and `is_broken`, implemented by the direct committer (tests, dedicated lanes) and by a handle to the shared thread. A host keeps its own sequence; the thread assigns lane ordinals.
6. **Membership.** Creating an index joins its lane (`join_members`, a head CAS that raises the membership epoch) and writes its first pointer and head-of-index objects; deleting seals it and leaves (a membership transition and a route tombstone). Membership is per index create and delete, never per write or per idle index. Lane identity derives from the node (policy tuple and a group id, at most the 4,096-member group ceiling per lane, a node with more indexes spanning several lanes by group id), so the lane is found without a LIST. **Incarnation.** Today an index's id is a pure function of its name and the incarnation is fixed at 1, so a recreate would find the old pointer and replay the old records. The index id (and shard id) of a created index therefore derives from the name and an incarnation the catalog binding hands out at create and records durably, and every id derivation (`served.rs`, the node, the dedicated-lane group) takes it; a name reused after a delete never reuses authority or history. M06.26 owns this change.
7. **Seal on open.** A node opening a lane writes nothing before it has scanned the tail (point 3) and established its writer epoch; an index whose base lives on another lane (promoted) follows the route as today.

**Rollback.** An older binary does not read `BASE`, so a version field cannot make it refuse. It reads `head.checkpoint`, which on a shared lane is the witness, and fails with `NotReady::Base` (it fails safe and opens nothing); on a dedicated lane without a pointer nothing changes. The format version of the pointer protects the other direction (a newer pointer an older new binary does not know is refused).

What this costs: (a) a write path with one more thread and a channel hop (a measured latency to bound in M06.25); (b) the head's cover can lag a crashed node's real minimum until the tail scan, so reclaim is delayed by one restart, never advanced early; (c) a host's base publish is two writes (objects, then pointer) instead of one head CAS, and the objects are unreachable until the pointer moves, so a crash between them leaves orphans; collection keeps every root at or above the live root's manifest generation, so an orphan is removed once a later root outranks it, as it is today; (d) lane-mates share a blast radius, as M03.09 accepted.

Rejected alternatives and why: A (cost, M03.09); B (a lane-wide base is not an index's base and rewrites all members to advance one); reading every member's pointer to compute the cover (requests scale with indexes, which the requests-scale-with-nodes-and-bytes rule forbids); a per-index timer to republish idle covers (an idle index must cost nothing).

Module, format and operational consequences: a new `BASE` pointer record in `hsearch-format` (an enveloped record with a magic, as the structural head is, and a format test); `recover` takes the pointer; `Publisher::activate`, `replace`, `compact` and `gc` write and read it instead of `StructuralHead::checkpoint` for an index with a pointer; `Serving` gains a log trait and `store::host` is generic over it; a new `store::lane_host` module owns the shared thread; `served::ServedIndex` joins and opens through the node's lane; the trait names the committer's `is_poisoned` (the `Serving` flag stays).

Migration, rollback and compatibility boundary: formats are not frozen and no data is deployed. A dedicated lane with a checkpoint still opens (the pointer is optional). Rolling back means reading a lane whose indexes have pointers with the older code, which does not read them: a node of the older code opens a pointer-bearing index as new and would replay from the lane start, so the pointer must carry a format version and the older code must refuse a pointer it does not know.

## Verification

Falsifiable conditions, exact tasks:

- **M06.24** adds the pointer with its successor rule, the format test, and moves host open, recovery, collection, snapshot pins, compaction and creation detection onto it for an index that has one. Recovery from the pointer equals recovery from the head's checkpoint on a dedicated lane; a crash between base objects and pointer leaves the old base serving; a stale writer's pointer CAS (an old version, and a lowered covered) is refused; a pointer of an unknown format version is refused; collection and a snapshot pin work on a pointer-bearing index.
- **M06.25** adds the shared committer and the `Serving` log trait. Hosts of several indexes write one lane, each killed and restarted at every step serving exactly its acknowledged writes; one slot carries records of more than one index; a fence loss breaks every host. The head cover stays 0 here, so no reclaim case is tested here and none is claimed; the channel hop is measured with a harness that commits through the direct and the shared path on the in-memory store (relative figure, provisional).
- **M06.26** adds membership, incarnation, seal on open and the pinned-set cover, and tests the histories that decide it, each of which must fail without its rule: an idle index restarted after the cover passed its pointer (replays from `max`); a host evicted or closed without publishing and then a cover advance (it cannot be evicted; closing publishes); a promoted index whose source lane is reclaimed before its new-lane base covers its seal; a deleted index not pinning the cover and its recreate not replaying the old records; an index that wrote a little and went idle not pinning the cover beyond the byte bound; the cover never passing a pinned record. Requests per acknowledged write are constant at 1, 100 and 1,000 indexes; requests per restart are a stated function of the tail (two per slot plus one pointer read per tail-set index) measured on a fixed tail workload, and with every index idle and published, constant; no LIST.
- **M06.21** is then the integration: the node on a shared lane with the kill-and-restart sweep at every step.

Reconsideration trigger: a measured channel hop above 10% of a commit's latency, or a tail scan that exceeds the replay limits on a lane the byte bound keeps bounded.
