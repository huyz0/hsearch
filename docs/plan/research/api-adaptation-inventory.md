# Selected API and adaptation inventory

Status: M02.01 work in progress. This records inspected sources and original fixture inputs, not a running reference deployment or hsearch API. The [core-v1 profile](../api-compatibility.md) remains the authority. Missing selected fixtures or unrun conformance block their own matching promises.

## Available source evidence

The earlier [repository audit](repository-audit.md) identifies the user's OpenSearch serverless fork at `ad254f6439dc4e93f5f00461b85a086e53a3d2da`. This inventory inspected its shell README, complete untruncated shell/testkit filename trees, and selected request-execution tests. It did not run those tests or inspect every handler. The fork is an available source of candidate histories; its test coverage and historical results are not hsearch evidence.

The fork's [document request tests](https://github.com/huyz0/OpenSearch/blob/ad254f6439dc4e93f5f00461b85a086e53a3d2da/serverless/testkit/src/test/java/org/opensearch/serverless/testkit/DocumentWriteRequestExecutionTests.java) exercise admitted IDs/source, create conflicts, sequence conditions, pipelines, generated IDs, data streams and response filtering. [Bulk tests](https://github.com/huyz0/OpenSearch/blob/ad254f6439dc4e93f5f00461b85a086e53a3d2da/serverless/testkit/src/test/java/org/opensearch/serverless/testkit/BulkRequestExecutionTests.java) include ordered mixed item errors, create behavior, external-version refusal, forced/waited refresh and shard-copy hints. Its mixed-error case uses structurally valid NDJSON with unsupported/invalid item semantics; it does not establish behavior for a malformed JSON tail. Hsearch's whole-request structural validation and independent item semantic failures must stay distinct.

[Update tests](https://github.com/huyz0/OpenSearch/blob/ad254f6439dc4e93f5f00461b85a086e53a3d2da/serverless/testkit/src/test/java/org/opensearch/serverless/testkit/UpdateRequestExecutionTests.java) expose document/script/upsert/condition/retry options. [Mapping tests](https://github.com/huyz0/OpenSearch/blob/ad254f6439dc4e93f5f00461b85a086e53a3d2da/serverless/testkit/src/test/java/org/opensearch/serverless/testkit/MappingRequestExecutionTests.java) include concrete index identity and stale recreation controls. [PIT tests](https://github.com/huyz0/OpenSearch/blob/ad254f6439dc4e93f5f00461b85a086e53a3d2da/serverless/testkit/src/test/java/org/opensearch/serverless/testkit/PointInTimeRequestExecutionTests.java) exercise admitted index/TTL and explicit refusal of ignored preference selectors. [Batch search tests](https://github.com/huyz0/OpenSearch/blob/ad254f6439dc4e93f5f00461b85a086e53a3d2da/serverless/testkit/src/test/java/org/opensearch/serverless/testkit/BatchSearchOptionsTests.java) make unsupported DFS/preference/template options visible. These statements concern this pinned fork, not every upstream OpenSearch deployment.

The selected engine's [workspace](https://github.com/huyz0/lucene-rust/blob/46e280bc2a208544fb36ecd95932e89cd8bc5618/Cargo.toml), already locked by hsearch, declares Apache-2.0 and contains index/search/analysis/store modules. Existing whole-file input and concurrency limitations in the audit still require M02.02-M02.04 experiments. A module's presence does not establish a supported adapter or remote reader.

Reference candidates are upstream OpenSearch 3.9.0 (`4ee42a94e87f66fbf1e62a9871b1b87f91e02472`) and opensearch-py 3.2.0 (`8991792d3fcdfc221c9aef62d7e82c3d15ff0206`). Official release/tag and native registry index/manifest identities were resolved on 1 November 2026. No reference image or client was installed or executed. The official client's upstream compatibility range is not a hsearch compatibility result. No third-party implementation/test source or binary is vendored.

No current application-specific production trace, client/proxy configuration or representative private dataset has been supplied or identified. The available fork request tests are being used as source context, not silently substituted for an application's actual workload.
