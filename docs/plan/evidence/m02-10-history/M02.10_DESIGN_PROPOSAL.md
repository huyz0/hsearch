## Storage/network and failure schedules

Each candidate has a test-only store with separate files per voter, serialization and actual file sync/atomic replacement/directory sync before its persistence acknowledgement. The format is research scratch, not hsearch persistence. Record write bytes/sync calls/errors and callback/Ready ordering. State-machine application occurs only for candidate-committed entries, with a separate applied prefix and independent immutable operation ledger. Any IO failure poisons that node until explicit restart; never acknowledge successful persistence after an injected error. No fsync latency is labeled power-loss durability or independent failure-domain replication.

Run these bounded histories for each candidate: healthy majority; isolate one voter then recover; isolate leader from both followers and show no successful unreplicated application before heal; hold both follower persistence acknowledgements, then release; successful commit whose client reply is deliberately suppressed and resolved by the same identity; graceful full shutdown/drop/reopen from actual persisted vote/log/membership/applied state; learner catch-up then voter addition/removal through library membership APIs; injected storage error and truncated persisted snapshot refusal. Bound each history to128 operations,4 nodes,4096 transport attempts,1MiB per message,16MiB total serialized transport and15s. Failure schedule execution must not depend on guessed sleeps alone: wait for explicit reached barriers, then assert, release or timeout visibly.

Persisted messages must be serialized/countable and delivered only under the library’s persistence contract. Snapshots and membership state are persisted before reporting install/application. Graceful reopen is labeled graceful reopen, not SIGKILL/power-loss qualification. Membership mechanisms may differ; report actual transitions and unimplemented/failed branches, not generic Raft equivalence.

Object faults:4 contenders x8 fixed CAS rounds against one shared ETag, with at most32 simultaneous attempts and explicit winner/conflict/error outcomes; a conditional retry after a known conflict counts its GET+retry; suppress a successful write response at the client wrapper, retain unknown and resolve exact stored identity; old ETag and occupied conditional-create refuse; immutable-payload/failed-root leaves a counted orphan. For conditional HTTP status, distinguish actual412/409/error and do not silently reclassify an unexpected result. This is injected response suppression after observed local success, not an observed provider transport failure.

Deliberately unsafe controls: falsely declare flush before the persisted file state, send persistence-dependent messages before storage, apply an uncommitted entry, blindly retry an unknown request with a new identity, omit one retry/response edge/KMS-model path, or substitute a closed-loop/offered trace. Independent ledgers/order traces must detect each. Bad cap/budget+one, duplicate/missing sample/profile/architecture/run/source/fixture bindings and missing native testcase reject. Preserve all existing tests/assertions and original source/coverage/CI controls.
