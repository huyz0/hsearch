# M03.05 evidence (increment 1): structural head, paged catalog, identity resolution

`provisional`: RustFS 1.0.4 (digest pinned in `scripts/rustfs.sh`) in a Docker container on a shared 4-CPU cloud VM, loopback, release build. No MinIO, no real S3, no network. Numbers are relative. Reproduce: `eval "$(scripts/rustfs.sh up)"; cargo run --release -p hsearch-lane --example catalog_profile -- 2000`. Counts are S3 adapter wire attempts (`S3Store::counts`).

## What is built

- **Formats** (`crates/format/src/authority.rs`, [formats.md](../formats.md)): kind 9 `StructuralHead`, kind 10 `CatalogRoot`, kind 11 `CatalogPage`, kind 12 `IdentityBinding`, and the derived keys `lanes/<domain>/<inc>/AUTHORITY`, `catalog/<id>/ROOT`, `catalog/<id>/pages/<bucket>`, `catalog/<id>/ids/<index>`.
- **Structural head** (`crates/lane/src/head.rs`): `create_head` (create-only, never recreated), `read_head`, `advance_head` with a closed set of transitions (`Establish`, `Checkpoint`, `Schema`, `Publication`, `Membership`). A transition is checked against `StructuralHead::validate_successor` **before any request**: one generation up, new token, same domain, incarnation and mode, activation, writer epoch, membership epoch, schema and publication generations and the cover only rising, the epoch inventory append-only. A lost CAS is `Advance::Lost` and changes nothing; a lost reply is resolved by the write's identity, and if that fails the answer is `Contended` and the caller must re-read. Nothing deletes a head.
- **Catalog** (`crates/lane/src/catalog.rs`): `2^bits` bucket pages (1 to 16 bits) chosen at creation, a name's bucket the leading bits of `SHA-256(catalog || name)`, so a name is found from keys alone. `create`, `delete`, `resolve`, `enumerate` (paged, cursor), `verify`. Each name edit is one conditional write of one page; names in different buckets never contend. A delete leaves a **tombstone** holding the identity it lost; `create` refuses that identity (`Invalid`) and the page successor rule refuses it on the wire format. A tombstone remembers only the last identity, so older ones are held by **identity bindings**: before a name goes live, `create` writes a create-only object per identity (`ids/<index>`, naming the name and the generation the create takes); an identity already bound can only be re-bound by a retry of the same create (same name, same generation, the lost-reply and crash-between-the-two-writes case), never after the name has moved on. So no identity a name has ever held, or any identity ever bound in the catalog, comes back, however many identities held the name in between (found by the independent review, which showed A, delete, B, delete, A resurrected A under the tombstone-only rule). A lost reply is settled by re-reading and deciding again (a repeated create or delete that already happened is a no-op), not by guessing.

## Tests

- Format: 14 tests (every-byte truncation and corruption, forged and over-bound fields, every regression of the head and page successor rules, bucket spread and the page bound against the body limit).
- Lane crate, in-memory store: 20 tests (A, delete, B, delete, A refused, and under another name; a create interrupted between its binding and its page retried; stale CAS loses and changes nothing, regression refused with zero requests, lost reply resolved by identity, unresolvable reply reported `Contended`, 4 threads x 15 establishes with the property one generation per success and the inventory exactly `1..=60`, 6 threads racing to create one name with exactly one winner, create/delete/recreate cycles from 4 threads, a create whose reply and resolve both fail settled by reading, paged enumeration complete and without tombstones, `verify` finding a misplaced page, request counts).
- RustFS: 2 tests (head CAS is 1 PUT and a stale version loses on the wire; 4 threads racing one name, no resurrection, reopen, zero LIST on the uncontended steps).
- **Seen red by hand** (each mutation made, the named test failed, the mutation reverted): the identity binding removed (three new lane tests failed), the checkpoint-root-swap rule disabled, resurrection check removed (`a_deleted_name_never_resurrects_its_old_identity`), `validate_successor` skipped in `advance_head` (`a_change_that_would_regress_is_refused_before_anything_is_written`), inventory append-only rule disabled (`a_successor_never_regresses_anything`), tombstone drop allowed (`successors_of_a_page_follow_the_rule`). They are not kept as a mutation suite.

## Requests and latency (RustFS, two runs, one host)

| step | n | PUT | GET | HEAD | LIST | p50 ms | p99 ms |
|---|---|---|---|---|---|---|---|
| head transition (version held) | 100 | 1.00 | 0.00 | 0.00 | 0 | 6.6-7.5 | 12.3-13.0 |
| head read (100 epochs in the inventory) | 100 | 0.00 | 1.00 | 1.00 | 0 | 2.2 | 3.0-4.0 |
| catalog create, 256 buckets, 2,000 names | 2,000 | 2.00 | 0.87 | 1.00 | 0 | 14.3 | 52.2 |
| catalog resolve | 286 | 0.00 | 1.00 | 1.00 | 0 | 2.0 | 2.5-3.3 |
| catalog enumerate, 100 per call | 21 | 0.00 | 13.1 | 13.1 | 0 | 30-32 | 35 |
| catalog create, 4 writers on 2 pages | 400 | 2.67 | 1.66 | 3.23 | **534** | 27.2 | **133** |
| `verify`, 256 pages | 1 | | | | 0 | 0.54 s | |

A transition is one PUT and no read because the caller already holds the version; a catalog create is one PUT for the identity binding and one for the page (2.00 PUT, 0.87 GET, 1.00 HEAD; the GET is absent for the first name in a bucket); a resolve is one HEAD plus one GET (the adapter's whole-object read). Enumeration visits about 13 buckets a call at this size (2,000 names over 256 buckets is about 8 names a page).

## Downsides, stated

- **A lost CAS race costs a version LIST.** On a 412 the S3 adapter looks for its own earlier accepted write (`find_accepted`, a `ListObjectVersions` plus a HEAD per candidate) before it reports a conflict. Uncontended paths show 0 LIST; four writers on two pages show about **1.3 LIST per create** and a p99 of 133 ms against 52 ms uncontended (before the identity binding was added, one PUT a create, the same race measured 0.95 LIST and a p99 of 208-252 ms; both runs are one host and noisy). "Hot paths need no LIST" therefore holds for the uncontended path and not under contention on one page. The way out is an adapter option that skips the scan when the caller settles by reading (the catalog does), which is an adapter change with its own downside (an own-write that landed is then settled by a read, not by identity) and is **not made here**; the fan-out (a name's bucket is one of up to 65,536) is what keeps unrelated names from racing.
- **Tombstones are kept for the life of the catalog.** A name used once costs an entry forever, bounded by distinct names ever used, not by churn (a name deleted and recreated 1,000 times is still one entry).
- **The fan-out is fixed at creation.** A bucket holds at most 2,048 entries (the encoder refuses the 2,049th, `TooLarge`, and changes nothing). 65,536 buckets give a ceiling of about 134M names a catalog and a page of about 150 names at 10M. There is no split: a catalog that outgrows its bits needs a new catalog and a copy (not built).
- **Enumeration is by bucket then name**, not alphabetical across buckets.
- **A create is two PUTs** (binding, then page) and one object per identity ever bound stays in the store. An identity whose create lost the race for a generation in an earlier call is refused if it comes back later (it was never bound, but cannot be told from one that was); the caller picks a new identity. A create whose reply was lost and whose name was then deleted by someone else reports `Invalid` although it had taken effect.
- **Head read is 2 requests.** A cold open that wants the head pays a HEAD and a GET; the caller that already holds a version pays none.

## Increment 2: promoted-lane routing, page repair, an exhaustive model

`provisional`: same RustFS 1.0.4 container as above, one host; the model runs on the in-memory store.

**Routing** (`crates/lane/src/promote.rs`). `promote` now creates the target's structural head (create-only, activation 1) between creating the target descriptor and the index leaving the source. `route(source, index)` is derived by key, no new object: the source descriptor lists the index, so `Shared`; it has left and the target's head exists, so `Promoted` at the head's activation and with its newest writer epoch; otherwise `Unrouted` (sealed but not established, or never a member). Between establish and leave the descriptor still lists the index while the source already refuses it with `Sealed`, so a caller treats `Sealed` as "route again". Measured on RustFS: promotion 4 PUT (seal slot, target descriptor, target head, source leave; was 3), no GET, HEAD or LIST; `route` of a promoted index 2 HEAD + 2 GET, no PUT, no LIST, 7.4 ms (one run). A crash after every prefix of a promotion never leaves two authorities (`routing.rs`: routed to the target implies the source refuses the index; the retry always ends `Promoted`).

**Page repair** (`Catalog::repair_page`). Rebuilds one bucket page that is missing or does not decode from the caller's claims `(name, identity, live)`. Each claim is checked against the identity's durable binding (it must exist, name this name, and the name must hash to this bucket), and an entry takes the binding's generation, plus one for a tombstone, so a tombstone keeps the identity and generation it had. The page is replaced by CAS on the unreadable object's version (create-only when absent); a healthy page is refused, and a racing repairer or editor loses with `Contended` (four threads racing: exactly one wins). Measured: 2 pages with 2 claims, 2 PUT, 4 GET, 4 HEAD, 0 LIST. Seen red: healthy page overwritten, binding check removed, bucket check removed, tombstone generation not raised, unconditional write; each failed a repair test.

**Exhaustive model** (`crates/lane/tests/model.rs`). Two names in one bucket, three identities, one head; operations create and delete a name for an identity, and the head's establish, checkpoint, schema and a deliberate regression. One scripted fault hits the n-th mutating request: refused, written with the reply lost and resolvable, with it lost and unresolvable, or preempted by another actor's operation (five different competitors) landing between the operation's last read and its conditional write. Checked after every step and after a clean retry of whatever ended unknown: no name resolves to an identity it lost and no create of one is acknowledged; an acknowledged create or delete reads back at once; `Exists` only for a name live under another identity; a name's generation never falls; an identity is live under at most one name; no page unreadable; head generation, epoch, cover, schema, publication and membership never fall, the inventory only appends and runs `1..=epoch`, one generation is one head; a regression is refused with zero requests; only documented errors occur.

| run | length | faults | runs |
|---|---|---|---|
| every push | 3 | up to 2 among the first 2 requests | 331,776 |
| every push | 3 | 1 among the first 4 | 135,168 |
| evidence (`--ignored`, release, once) | 3 | up to 2 among the first 4 | 1,708,032 |
| evidence (`--ignored`, release, once) | 4 | 1 among the first 4 | 2,162,688 |

Seen red (each mutation, one run, the model failed): resurrection allowed, the identity binding skipped, the already-settled arm of create turned into `Exists`, a tombstone not raising the name generation, the head's successor check skipped, the epoch number off by one. Not in the model: page repair (it is covered by `repair.rs` examples and a four-thread race, including an oversized page, not enumerated), so "generation never falls" is not exercised across a repair; repair restarts a page's commit counter at 1 and an entry takes the binding's generation, which equals the original for a name deleted once. Not run: more than two faults, more than two names, any history longer than four operations, a second head or catalog, and concurrent (not interleaved) actors: the preempting actor acts between a read and its write, which is the race a CAS loses, but actors are never truly parallel in the model (the threaded races are in `authority.rs`, `repair.rs` and `rustfs.rs`).

**Downsides.** Promotion costs one more PUT. Repair trusts the caller's completeness and `live` flags: a name left out of the claims is forgotten and a forgotten tombstone, or a deleted identity claimed `live`, lets its identity be bound again at its old generation (the name's generation falls), which the binding cannot detect: "no resurrection after a repair" holds only if the claims are right. A promotion completed before this change has no target head, so `route` reports it `Unrouted` for good (nothing is released yet); a repeat promotion also checks that an existing head has the policy's mode. The model's per-push bounds are small (about a minute and a half in debug together); the larger ones were run once. `route` costs two reads for a promoted index and says nothing about a writer that already holds a stale descriptor except through the source's `Sealed` refusal.

## Not done (named, not claimed)

- The lane reads the head through `LaneWriter::open_with_head` (M03.08, increment 2); a lane opened by `open` still uses the `COVER` marker, never both. A checkpoint root that moves the cover is M06's.
- Name to descriptor resolution (the index and shard descriptor bodies) is M05/M06; the catalog resolves a name to an opaque identity only. Alias semantics, case and Unicode normalisation of names belong to the API layer; the catalog accepts 1 to 255 bytes of UTF-8 without a control character.
- `verify` reports a bad page; `repair_page` rebuilds one from caller claims, and the claims' completeness and liveness come from the index descriptors (M05/M06).
- Fan-out growth (a catalog split) is still not built.
- The model is bounded as stated in increment 2.
