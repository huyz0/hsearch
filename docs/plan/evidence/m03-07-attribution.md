# M03.07 attempt, path and cost attribution

`provisional`: implemented and tested in `crates/s3` (`ledger.rs`, `traffic.rs`, wired into `S3Store`), against a scripted in-process provider with its own transport log. No real provider, route inspection or billing export was touched.

## What exists

- **Logical calls and attempts are counted apart.** `Ledger` records one logical call per adapter operation and one attempt per request on the wire, by role (payload, metadata, key), verb and outcome (ok, conflict, empty read, throttled, server error, client error, transport), with encoded request and response bytes. Amplification is reported as a pair of integers, attempts and calls, so no rounding hides it. A call refused before the wire has no attempt.
- **Logical calls are counted at every public entry**, including a call refused before the wire (a conditional update through `create`, or a budget too small), which is one logical call and no attempt. Bucket setup, version verification, version delete and the probe helper count too.
- **Hidden requests are visible.** A write that loses a race pays one PUT plus one LIST for resolution; the scripted test shows 1 logical call and 2 attempts (Put/Conflict, List/Ok) for the metadata role. An empty read, a throttled write and a connection that never answers are each an attempt with their own outcome.
- **Roles.** The object-backend calls are `Payload`, the metadata-store calls and bucket setup are `Metadata`. `Key` exists in the ledger but nothing in this crate feeds it: key operations are a KMS adapter's, so the key role is empty here until M05.08/M15.01 wire it.
- **Redirects are not followed** (`max_redirects(0)`): a followed redirect would send a second request inside one call that no counter could see. A 3xx is a client-error attempt.
- **Directed traffic ledger.** `TrafficLedger` keeps encoded bytes by (role, direction, endpoint, price class, payer) where the class is same zone, cross zone, cross region, NAT processing, NAT hairpin, or unknown. A transfer is counted once however many ends report it (a repeat id with different bytes is a counted disagreement). Keys (256), remembered transfers (4,096), tenants (64) and name length (128) are bounded with an overflow bucket, and bytes refused by a bound are kept as unknown traffic rather than dropped (the adapter records through `record_unique`, which keeps no id table, because it reports each transfer once; a review found that the first version silently stopped recording after about 2,048 requests, and a test now drives 2,100); a tenant drill-down returns only the named tenant's totals.
- **Unknown is not free.** A path with a missing region, zone or payer, unverified evidence (`DnsOnly` or `Declared`), or a class with no rate is priced as unknown bytes, never zero. A `DnsOnly` path fails `acceptance()` outright. Until `S3Store::with_path` is called the adapter's path is unknown.
- **Units are part of the rate.** `Rate::per(micro_usd, Unit::GB | Unit::GiB)` stores the byte unit; cost rounds up, so 1 GiB at a per-GB rate costs 10,738 where a per-GiB rate costs 10,000 per 10,000, and a request is never free.
- **Reconciliation.** `reconcile(ledger, observed_verbs)` returns every verb whose adapter count and independent count differ. `reconcile` compares **verbs only**. The scripted provider is written in this repo and keeps its own log; it classifies a GET with a `versions` query as LIST, which mirrors the adapter's rule, so that part of the agreement is partly circular. The adapter's counts and the log agree for a clean write, a lost race, an empty-read/throttle/success sequence and a redirect; outcomes, bytes beyond a bound, and the PUT/POST split are not checked against the log.

## Tests

- 24 unit tests in `hsearch-s3` plus 10 in `tests/attribution.rs` (the integration file needs no external store). Mutations each seen red: dropping the transport-failure attribution, hardcoding the role in the resolution listing, removing transfer de-duplication, accepting DNS-only evidence, reading GB as GiB, recording through the table-limited path (the 2,100-request test), and following redirects.
- Line coverage of `hsearch-s3`: see the pull request; 97.89% of lines (ledger.rs 100%, traffic.rs 99.9%, lib.rs 94.8%) with the RustFS integration tests present.

## Limits and what is not done

- **Request size is a lower bound.** It is computed from the request line and the headers the adapter signs plus the body, not read off the socket: the HTTP client adds a few headers of its own (one 13-byte PUT measured 653 counted against 710 on the wire, a 57-byte gap; the test allows up to 80). A connection refused or unresolved sent nothing and is attributed zero bytes; any other transport failure is attributed the whole request. A body read that fails midway attributes the headers but not the partial body. Response size is the header lines and body plus a 15-byte status line with an empty reason phrase. Both are plain HTTP; TLS overhead is not counted.
- **The adapter does not retry.** SDK-level retries are injected only as a caller repeating a call (a second logical call) and as `retry` flags a test passes to `Ledger::attempt`; no real SDK or retrying layer was run, so the validation item "inject SDK retries" is only partly met. NAT/hairpin paths and double-counted endpoint charges are exercised in the ledger's unit tests, not through the adapter. M03.12 later added an opt-in retry layer and the through-the-adapter hairpin test.
- **Infrastructure route and endpoint inspection, a real NAT/hairpin path and a real provider usage export are not done.** The ledger takes the inspection result as input (`Path` with its `Evidence`); producing it from a real VPC and checking it against bills is M15.07's, which now names this feed. The synthetic provider usage is the transport log of the scripted provider.
- Multipart and POST attribution, the tenant identity at the adapter (it passes none, so tenant totals are fed by callers through `TrafficLedger::record`) and the bounded OpenTelemetry export in `hsearch-observe` are not done; M03.12 added retries and POST attribution; the tenant feed and the telemetry export are M08.02's.
- DELETE returning 404 is classified as an empty read.
