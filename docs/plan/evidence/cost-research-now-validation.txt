## Bounded fence model

- serialized_poisoned_retained: safe=True, states examined=23.
- BUG_two_inflight: safe=False, states examined=44.
  Counterexample: issue record 0; issue record 1; PUT/ack record 1; successor fences slot 0.
- BUG_continue_after_failure: safe=False, states examined=44.
  Counterexample: issue record 0; successor fences slot 0; record 0 collides with occupied slot; issue record 1; PUT/ack record 1.
- BUG_deleted_fence: safe=False, states examined=25.
  Counterexample: issue record 0; successor fences slot 0; BUG: GC deletes fence; PUT/ack record 0.

The correct model covers one old writer, one successor, three record identities, atomic conditional create, failure poisoning, and a retained fence. It excludes full activation/ownership, idempotency, actual provider retries/linearizability, multiple terms, checkpoint/GC, same-term reopen and crypto. Runtime implementation must prove those separately. Bad controls are intentionally unsafe.

Each batch in the raw JSON counts payload+CAS, fenced+inline-envelope, and fenced+separate-envelope variants. KMS calls remain one per fresh batch; an inline wrapped key saves an object PUT, not a KMS request. Two checkpoint PUTs are charged every 64 batches, and per-domain activation is shown separately rather than multiplied into a steady-state monthly claim.
