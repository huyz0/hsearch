### M23.02: Serve IVF with and without quantization

Status: **planned**. Owner role: engine/search.

Goal: Second vector variant (PR-22).

Depends on: M23.01.

Deliverables:

- IVF mapping and query (`nprobe`, rerank) using lucene-rust's `lucene-ivf` and the shared quantizer trait
- Update, delete and merge behaviour of write-once IVF segments stated and tested

Validation:

- Recall@10 and latency on the stated corpus; delete a fraction and merge; compare with HNSW at equal recall

Definition of done:

- Recall@10 meets its floor
- The mapping parameters OpenSearch users set map to a variant or are refused with a reason

### M23.03: Serve disk-based HNSW and IVF from the object store

Status: **planned**. Owner role: engine/search.

Goal: Read vector data by range from the object store instead of loading it (PR-22, PR-53).

Depends on: M23.02, M04.02.

Deliverables:

- Disk-based HNSW (`lucene-disk-hnsw`) and a disk-oriented IVF layout reading by range through the M04.02 input; where M02.12 confirmed the IVF layout is missing, an additive lucene-rust PR and a pin bump
- Cold and warm query reports with range counts per query

Validation:

- Query a corpus larger than the cache cold and warm; count GETs and bytes per query; recall floor holds

Definition of done:

- Range reads per query are bounded and reported, and recall stays above its floor
- No change alters what an existing OpenSearch deployment reads or writes
