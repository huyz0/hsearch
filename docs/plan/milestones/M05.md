# M05: mTLS, tenant policy and BYOK

Generated from `tasks.json`; edit the ledger and run `python docs/plan/tools/plan.py render`.

Status: **planned**. Owner role: security/crypto.

## Goal

Deliver identity/authorization and portable envelope encryption before production data formats are activated.

## Completion prerequisites

M03

Task-level dependencies determine when individual tasks can start. Milestone prerequisites gate completion.

## Definition of done

- All peer roles require validated mTLS identity and scoped authorization, with rotation and negative handshake evidence.
- Object/WAL/key formats use authenticated bounded blocks and vetted crypto; no plaintext production spill path is left unaccounted for.
- Wrap/unwrap providers, rotation, revocation and hardware dispatch have executable conformance evidence; real cloud providers close in M15.

## Tasks

### M05.01: Implement identity and role authorization

Status: **planned**. Owner role: security/crypto.

Goal: Keep client, peer, admin and replication authority separate.

Depends on: M03.

Deliverables:

- IdentityProvider, verified principal types, policy generations, dev CA and SPIFFE/file adapters

Validation:

- Wrong CA/SAN/cluster/role, expired cert, public-token peer access and tenant spoof tests.

Definition of done:

- Every peer RPC has explicit role/tenant checks and cert verification cannot be disabled by ordinary config.
- Principal, policy, quota and key scope are the index (tenant = index); no policy object spans several indexes

### M05.02: Implement key-provider contract

Status: **planned**. Owner role: security/crypto.

Goal: Make key wrapping replaceable without exposing key material.

Depends on: M03.

Deliverables:

- KeyProvider API, isolated test KMS, provider errors, bounded DEK cache and audit schema
- Per-index key references with a deployment default key for indexes that have none (PR-24); the DEK cache keeps KMS calls off the per-request path

Validation:

- Wrap/unwrap context/version mismatch, throttle/denial/timeout, cancellation and zeroization checks.
- Mixed-key test; KMS call count stays inside the cache policy; revoking one index's key blocks reads of that index only

Definition of done:

- Plaintext keys never enter logs/evidence; test provider is refused in production profile.

### M05.03: Ratify encrypted block format

Status: **planned**. Owner role: security/crypto.

Goal: Make portable authenticated random access safe.

Depends on: M05.02, M03.03.

Deliverables:

- Reviewed envelope/header/AAD/nonce specification, AEAD codec and vectors
- Bounded inline initial wrapped-DEK envelope and authenticated object/domain binding; optional external rewrap overlay selected by published metadata/policy

Validation:

- Known-answer and independent decrypt; header/block substitution, every-byte damage, retry/crash nonce controls.
- Verify inline and rewrapped keys, wrapper/context substitution, crash before overlay publication, revoked old policy and unchanged ciphertext AAD; never accept an unauthenticated provider wrapper

Definition of done:

- One fresh DEK per immutable object; only authenticated plaintext reaches parsers; format has explicit size/invocation bounds.

### M05.04: Encrypt every persistent data path

Status: **planned**. Owner role: security/crypto.

Goal: Cover object data, logs, cache and engine scratch.

Depends on: M05.03.

Deliverables:

- Encryption decorators, encrypted-volume/directory readiness policy, spill inventory

Validation:

- Inspect on-disk object/journal/cache/spool bytes; verify engine scratch volume policy and fail unprotected production startup.

Definition of done:

- Object encryption cannot be claimed as full at-rest protection while engine scratch remains plaintext.

### M05.05: Implement rotation and revocation state machines

Status: **planned**. Owner role: security/crypto.

Goal: Retire key versions without breaking pinned readers or promising instant revocation.

Depends on: M05.01, M05.04.

Deliverables:

- Immutable envelope rewrap publication, dependency inventory, policy invalidation and bounded key/reader TTL
- Crypto-shredding by destroying an index's key (PR-26) and the audit log of rotation and revocation (PR-27)

Validation:

- Concurrent rewrap/PIT/GC/restart, KMS outage, revoked cached key and policy partition histories.
- After key destruction the index's objects and caches cannot be read; the audit log records rotation, revocation and destruction

Definition of done:

- Old roots keep needed envelopes; expired policy fails closed; measured revocation envelope is documented.
