# M14: Performance kernels and native hardware

Generated from `tasks.json`; edit the ledger and run `python docs/plan/tools/plan.py render`.

Status: **planned**. Owner role: performance.

## Goal

Optimize measured bottlenecks while preserving reference behavior on ARM and x86.

## Completion prerequisites

M04, M05, M07, M09

Task-level dependencies determine when individual tasks can start. Milestone prerequisites gate completion.

## Definition of done

- Release x86_64/aarch64 paths run natively and all accelerated kernels match scalar/reference boundary cases.
- Unsafe additions have safety proofs, applicable tooling and measured whole-system benefit; fallback remains supported.
- Cold/warm/open-loop measurements meet frozen targets or remain explicit release blockers.
- Performance changes improve a measured cost/latency Pareto point or justified constraint; request/byte/compaction/KMS amplification is included.

## Tasks

### M14.01: Establish profiles and noise-aware regression gates

Status: **planned**. Owner role: performance.

Goal: Choose optimizations from actual end-to-end costs.

Depends on: M04, M05, M07, M09.

Deliverables:

- CPU/IO/alloc/network/lock profiles, paired baselines and benchmark threshold policy

Validation:

- Repeat/interleave runs with configuration hashes; quantify CI/dedicated-worker variance.

Definition of done:

- No hardware optimization is justified solely by microbench marketing or uncontrolled CI timing.

### M14.02: Optimize remote I/O, cache and batching

Status: **planned**. Owner role: performance.

Goal: Reduce dependent reads/requests and refresh/merge overhead.

Depends on: M14.01.

Deliverables:

- Measured block/prefetch/pack/cache/commit policies with bounded speculative work

Validation:

- Cold/warm/mixed load, read/write amplification, compaction interference and archive-stall tests.
- Measure useful bytes versus prefetched/packed/rewritten/retained bytes plus cache/metadata/KMS request amplification.

Definition of done:

- Latency/cost improve without changing durability/freshness; working set exceeds cache during cold qualification.

### M14.03: Implement target-dispatched SIMD kernels

Status: **planned**. Owner role: performance.

Goal: Accelerate hottest decode/search/vector paths where engine hooks permit.

Depends on: M14.01.

Deliverables:

- Scalar and SSE/AVX2/NEON paths; optional AVX-512/SVE capability adapters

Validation:

- Property/differential tests for tails/alignment/NaN/overflow, force-disabled features and native x86/ARM runs.

Definition of done:

- Unsupported CPUs never execute new instructions; no precision/relevance change is hidden.

### M14.04: Audit unsafe and optional system acceleration

Status: **planned**. Owner role: performance.

Goal: Use low-level changes only with proofs and fallback.

Depends on: M14.02, M14.03.

Deliverables:

- Narrow unsafe kernels, safety docs, Miri/ASan corpus; optional io_uring/NUMA/allocator experiments

Validation:

- Bad-length/lifetime/alias controls; resource saturation; normal-IO fallback on unsupported kernel.

Definition of done:

- Each accepted unsafe/system change has an observed bottleneck and end-to-end win; rejected experiments stay documented.

### M14.05: Qualify hardware encryption performance

Status: **planned**. Owner role: performance.

Goal: Verify cipher backend dispatch and quantify security cost.

Depends on: M14.01, M05.

Deliverables:

- AES-NI/PMULL and software-path results, optional VAES trial, key-cache/throughput profiles

Validation:

- Paired encrypted/plaintext query/ingest/copy, KMS cold/cache-hit and no-acceleration runs.

Definition of done:

- Selected backend and all safety checks are observable; encryption is not bypassed to meet a benchmark.

### M14.06: Close performance acceptance

Status: **planned**. Owner role: performance.

Goal: Meet or explicitly fail frozen service budgets.

Depends on: M14.04, M14.05.

Deliverables:

- Release-profile L1 benchmark/cost report and regression artifacts

Validation:

- Open-loop supported query/write mix with overload/recovery, native ARM/x86 and background maintenance.

Definition of done:

- All required targets and correctness gates pass; unresolved target misses block matching release claims.
