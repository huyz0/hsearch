# M24: Extension modules: native C ABI and WebAssembly

Generated from `tasks.json`; edit the ledger and run `python docs/plan/tools/plan.py render`.

Status: **planned**. Owner role: extensions/runtime.

## Goal

Load external modules that add analyzers, query types, ingest processors and scoring functions, with no JVM and no scripting plugins.

## Completion prerequisites

M07

Task-level dependencies determine when individual tasks can start. Milestone prerequisites gate completion.

## Definition of done

- An example module built outside the workspace loads on a running node as a native C-ABI module and as a WASM module and returns identical results.
- A version mismatch is refused, a disabled module is absent, and a WASM module that traps or exceeds its limits is stopped while the node keeps serving.
- `unsafe` exists only in the loader crate, with a written safety proof.

## Tasks

### M24.01: Specify the module ABI, host interface and extension points

Status: **done**. Owner role: extensions/runtime.

Goal: Fix the contract before any loader code (PR-23, D18).

Depends on: M19, M20.04.

Deliverables:

- Versioned C-compatible ABI for in-process shared libraries and a versioned WASM host interface; both declare name, version, required engine API version and extension points (analyzers, query types, ingest processors, scoring functions)
- Bounded buffers with explicit ownership, enablement by node configuration and node role, refusal of an unsupported API version, failure semantics per model (native in-process is trusted and can take the node down; WASM and out-of-process are isolated); a separate-process RPC model stays optional

Validation:

- Review the spec against the example module's needs; golden ABI header and host-interface fixtures

Definition of done:

- The spec states what each model can and cannot isolate
- No extension point lets a module read files, sockets or memory outside what the host grants

Evidence:

- [evidence/m24-01-extension-abi-spec.md](../evidence/m24-01-extension-abi-spec.md): ABI 1.0 and engine API 1.0 specified in docs/plan/extension-modules.md with a per-model isolation table, wire encodings for the four extension points, enablement and mapping binding. Golden C header, struct layout, WASM host interface and example descriptor under fixtures/extensions/abi-v1, held by tools/tests/test_extension_abi.py (header mutations observed to fail it). Documentation only: nothing measured; native modules are isolated by interface, not enforcement; layout not run on aarch64; wire format fixed with golden vectors.

### M24.02: Build the native module loader crate

Status: **done**. Owner role: extensions/runtime.

Goal: The one place `unsafe` is allowed (PR-23, D18, conflict 11).

Depends on: M24.01.

Deliverables:

- One dedicated loader crate for library open, symbol lookup and ABI calls, with a written safety proof and tests; the rest of the workspace keeps `unsafe_code = "forbid"`
- AGENTS.md rule and the existing workspace check amended to name that single crate; no new gate

Validation:

- Load a valid module, a wrong-version module, a missing-symbol module and a module that returns malformed buffers; sanitizer or Miri run where it applies

Definition of done:

- `git diff Cargo.toml` shows the exception and nothing else widens `unsafe`
- A node refuses a module whose declared API version it does not support

Evidence:

- [evidence/m24-02-native-loader.md](../evidence/m24-02-native-loader.md): Native loader crate hsearch-module-native (unsafe only in mod sys, with a written safety proof) over the shared hsearch-module-abi crate; workspace.py and AGENTS.md name the single exception. 26 loader tests against real C shared libraries (valid, wrong version without other symbols resolved, missing symbol, malformed buffers, overrun, hang with quarantine, busy, dependency refusal, hash pin), layout held to layout.json. Miri, ASAN, TSAN and valgrind clean on x86_64 Linux; six mutations caught; line coverage 98.09% and 96.11%. Pooled call p50 28.6 us at 64 B against 27 ns direct: the thread hop, which is the platform floor (bare ping-pong 26.2 us), provisional on a 4-vCPU VM; zero allocations per steady-state call. Linux x86_64 only: not run on aarch64 or macOS; not yet wired to a node (M24.04).

### M24.03: Choose and embed the WASM runtime with enforced limits

Status: **done**. Owner role: extensions/runtime.

Goal: A sandboxed option for less-trusted extensions (PR-23).

Depends on: M24.01.

Deliverables:

- Runtime selection with exact pin, licence inventory and a build-size and compile-time note; limits on memory, CPU (fuel) and host calls; a host interface that grants no files or sockets
- A trap or limit breach stops that module and leaves the node serving

Validation:

- Modules that trap, exhaust memory, exhaust fuel and attempt a forbidden host call; the node keeps serving in each case

Definition of done:

- The runtime is pinned and licence-checked before adoption
- A WASM module cannot read files, sockets or memory outside what the host interface grants

Evidence:

- [evidence/m24-03-wasm-runtime.md](../evidence/m24-03-wasm-runtime.md): WASM host crate hsearch-module-wasm on wasmtime 50.0.1 (exact pin, Cranelift only, no WASI) over the shared hsearch-module-abi crate; linker grants only hsearch_host_v1.log and .cancelled, so any other import is refused at load; limits on declared memory maximum, fuel, wall-clock deadline (epoch), host calls and stack; a trap or breach discards that instance, counts a strike and leaves the module serving, three strikes in 60 s fail it. 36 tests over WAT modules (trap, stack overflow, fuel, deadline, memory, forbidden import, host-call budget, version and descriptor refusals, init on every instance, strikes, concurrency, queueing); two independent reviews fixed (init on every instance, load timeout, no strike for caller deadlines, shutdown, slot guard, bounded memory reservation); thirteen mutations caught; line coverage 95.93%. Runtime chosen by measurement: wasmtime about 8x faster than wasmi per byte (133 ns vs 884 ns at 64 B) at the cost of 112 crates, a 214 s clean build and a 13 MB stripped binary; fuel and epoch add 30-45% and 15-30% on a tight loop. Host call 555 ns p50 at 64 B (no thread hop). Provisional on a 4-vCPU VM, Linux x86_64 only, not yet wired to a node (M24.04).
