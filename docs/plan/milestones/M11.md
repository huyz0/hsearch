# M11: Independent cross-cluster copy module

Generated from `tasks.json`; edit the ledger and run `python docs/plan/tools/plan.py render`.

Status: **planned**. Owner role: copy-module.

## Goal

Deliver resumable one-time copies with independent destination storage and encryption.

## Completion prerequisites

M10

Task-level dependencies determine when individual tasks can start. Milestone prerequisites gate completion.

## Definition of done

- Two separate RustFS deployments complete a snapshot-cut copy with destination policy and bounded resources.
- Pause/resume/cancel and process loss cannot mix source cuts, duplicate activation or delete unrelated data.
- Completed destination recovers/searches after source network, storage and KMS access are blocked.
- A full portable snapshot restores on a different provider and is independent of the source store afterwards (PR-51).

### M11.03: Implement pause, cancel and cleanup

### M11.05: Qualify copy module end to end

Status: **planned**. Owner role: copy-module.

Goal: Close copy behavior and observability acceptance.

Depends on: M11.04, M08.

Deliverables:

- Two-cluster fault campaign, cost/throughput report and operator/AI runbook

Validation:

Definition of done:

### M11.06: Take full portable snapshots and restore them across clouds

Status: **planned**. Owner role: replication/storage.

Goal: A self-contained snapshot that restores on another provider (PR-51).

Depends on: M11.04, M22.05.

Deliverables:

- Full snapshot copying all segments, manifests and metadata and referencing nothing in the source store; cross-cloud restore as a deep-copy job on the copy machinery: resumable, throttled, checksum and manifest verified, cost and egress reported before it starts
- Explicit key story: the destination index uses a key the destination can reach, or is re-encrypted under a new key

Validation:

- Snapshot on one provider and restore on another through the provider conformance suite (RustFS plus a second provider here, real clouds in M15): identical results on a shared query set; kill mid-job and resume without duplicating or losing objects; the destination keeps working after the source bucket is deleted

Definition of done:

- The restored index depends on nothing in the source store
- Bytes and request counts are reported and match what was metered
