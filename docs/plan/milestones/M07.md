# M07: Distributed routing and query serving

Generated from `tasks.json`; edit the ledger and run `python docs/plan/tools/plan.py render`.

Status: **planned**. Owner role: query/cluster.

## Goal

Scale query/index roles independently with mTLS and explicit freshness/completeness.

## Completion prerequisites

M06

Task-level dependencies determine when individual tasks can start. Milestone prerequisites gate completion.

## Definition of done

- Multiple nodes accept routed writes and fan out queries with correct document routing, reduce semantics and tenant isolation.
- Latest/at-least/PIT reads validate receiver checkpoints; stale placement cannot downgrade freshness.
- Node loss, hot tenant overload and shard movement preserve declared results or return explicit incomplete/unavailable status.
- Zone-local serving and eligible fallback pass normal and zone-loss cost/capacity tests; direct object access is compared with paid cross-zone peers.

### M07.05: Implement replica freshness and PIT

### M07.07: Deliver zone-local serving and cost-aware read placement

Status: **planned**. Owner role: cost/architecture/operations.

Goal: Avoid routine cross-zone fanout/cache bytes while keeping required reader eligibility and surviving capacity.

Depends on: M03.07, M07.05.

Deliverables:

- Zone-local ingress/coordinator/worker cells, eligible fallback, object-versus-peer cache selection and bounded prewarm

Definition of done:

- Cost ranking runs only after authorization/freshness checks; strong reads never silently downgrade
- Normal/recovery fanout, duplicated caches and rejected traffic are accounted for; resilient profiles demonstrate surviving capacity
