# M04: Lucene Rust bridge and committed readers

Generated from `tasks.json`; edit the ledger and run `python docs/plan/tools/plan.py render`.

Status: **planned**. Owner role: engine.

## Goal

Deliver a production-shaped engine adapter with remote I/O and exact commit/visibility boundaries.

## Completion prerequisites

M02, M03

Task-level dependencies determine when individual tasks can start. Milestone prerequisites gate completion.

## Definition of done

- Native adapter supports the frozen mutation/query contract and old-index reopen with Java/reference oracles.
- Range-native reads operate with bounded memory and instrumented remote requests; materialized fallback is separately measured.
- Only committed operations enter serving readers, with preserved identity, pinned query/fetch generations and deterministic replay.

## Tasks

### M04.01: Implement engine adapter and revision isolation

Status: **planned**. Owner role: engine.

Goal: Keep upstream churn behind one tested public boundary.

Depends on: M02, M03, M19.

Deliverables:

- EngineFactory/ShardEngine APIs, native lifecycle implementation and feature inventory

Validation:

- M02 corpus against pinned engine; missing feature, unsupported writer mode, panic/corruption handling.

Definition of done:

- No runtime crate bypasses the adapter to engine internals; revision upgrade has a dedicated test command.
- Only selected core-v1 capabilities are promised; unsupported engine/API features remain explicit and cannot be silently ignored.
- hsearch holds no vendored copy or private patch of lucene-rust (`git grep` finds none); each engine change is a linked lucene-rust PR plus a pin bump, with the bridge contract and old-index corpus passing at the new pin (PR-53)

### M04.02: Deliver remote-input engine changes

Status: **planned**. Owner role: engine.

Goal: Make lazy object reads real through all affected readers.

Depends on: M04.01.

Deliverables:

- Additive lucene-rust PR series (range-native input behind a new abstraction; nothing that changes what an existing OpenSearch deployment reads, writes or calls), then an exact pin bump in hsearch (PR-53), read-at input implementation, bounded I/O/cache bridge

Validation:

- Remote/cold corpus across affected codecs with cache smaller than corpus and injected errors/timeouts.

Definition of done:

- Remote reads do not require full-file heap residency; published cold path includes measured range counts.

### M04.03: Build resolved-operation preparation

Status: **planned**. Owner role: engine.

Goal: Evaluate conditional mutations once against committed state.

Depends on: M04.01.

Deliverables:

- Canonical operation identity/version map, partial-document, upsert and no-op resolver for _update including if_seq_no and if_primary_term (scripts stay out, A11) and idempotency outcome storage

Validation:

- Dependent updates/create races; failed commit after preparation; replay with time/random input changes.

Definition of done:

- Speculative state cannot influence a committed dependent mutation; replay never reruns nondeterministic scripts.

### M04.04: Implement apply and reader barriers

Depends on: M04.03.

### M04.05: Integrate cache, materialization and merges

Status: **planned**. Owner role: engine.

Goal: Bound indexing/read resources and immutable file lifetime.

Depends on: M04.02, M04.04.
