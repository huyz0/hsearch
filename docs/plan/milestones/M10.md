# M10: Snapshot, export and change-stream contracts

Generated from `tasks.json`; edit the ledger and run `python docs/plan/tools/plan.py render`.

Status: **planned**. Owner role: storage/export.

## Goal

Create shared primitives for backup, independent copy and continuous replication.

## Completion prerequisites

M07, M09

Task-level dependencies determine when individual tasks can start. Milestone prerequisites gate completion.

## Definition of done

- A snapshot cut pins all segment, schema, key and committed-tail dependencies before it is exported.
- Change stream provides ordered resolved operations and explicit gaps/retention over both durability modes.
- Destination import staging is durable and hidden until verified activation; contracts are public and module independent.

## Tasks

### M10.01: Implement snapshot barrier and durable pins

Status: **planned**. Owner role: storage/export.

Goal: Capture a complete recoverable cut, including unarchived tail.

Depends on: M07, M09.

Deliverables:

- Snapshot descriptor, vector checkpoint, coordinated pin creation/renewal and base+tail inventory

Validation:

- Concurrent writes/GC, quorum archive lag, pin expiry/renewal response loss and multi-shard capture.

Definition of done:

- No acknowledged operation before the declared cut is omitted; snapshot consistency scope is explicit.

### M10.02: Implement export and logical reindex paths

Status: **planned**. Owner role: storage/export.

Goal: Support physical-compatible and format/topology-changing transfers.

Depends on: M10.01.

Deliverables:

- Versioned file/schema export API, scoped grants, logical document iterator and format negotiation

Validation:

- Unsupported engine/cipher, source recreation, bounded batches and traversal/SSRF controls.

Definition of done:

- Export binds source UUID/incarnation/cut and never exposes long-lived provider secrets.

### M10.03: Implement committed change stream and retention leases

Status: **planned**. Owner role: storage/export.

Goal: Supply durable ordered CDC without unbounded history.

Depends on: M10.01.

Deliverables:

- Resolved-op stream, schema/topology events, replay ranges, lease budgets and gap responses

Validation:

- Duplicates, gaps, lease expiry, slow consumer and source split/format upgrade histories.

Definition of done:

- Consumers cannot acknowledge beyond durable source prefix; expired history requires explicit rebootstrap.

### M10.04: Implement destination import transactions

Status: **planned**. Owner role: storage/export.

Goal: Checkpoint verified data before making it public.

Depends on: M10.02.

Deliverables:

- Private staging index, verified chunk ledger, source/local sequence map and activation CAS

Validation:

- Crash after transfer/before progress/after activation, name collisions and tampered chunk hashes.

Definition of done:

- Resume is idempotent; incomplete destination never appears searchable through active aliases.

### M10.05: Qualify external consumers and disabled modules

Status: **planned**. Owner role: storage/export.

Goal: Prove reusable contracts without controller coupling.

Depends on: M10.03, M10.04.

Deliverables:

- Example snapshot/change-stream client and import conformance suite

Validation:

- Build without copy/CCR and exercise export/snapshot; scope denial and unsupported version controls.

Definition of done:

- Core contracts work independently and match both object and quorum sources.
