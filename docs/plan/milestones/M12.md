# M12: Cross-cluster replication module

Generated from `tasks.json`; edit the ledger and run `python docs/plan/tools/plan.py render`.

Status: **planned**. Owner role: replication-module.

## Goal

Deliver asynchronous follower-pull replication with bounded history, explicit lag and safe promotion.

## Completion prerequisites

M10

Task-level dependencies determine when individual tasks can start. Milestone prerequisites gate completion.

## Definition of done

- Follower bootstrap and continuous resolved-operation replication preserve source identity/schema under restart and at-least-once delivery.
- History/lease budgets, read-only enforcement, pause/resume/expiry/rebootstrap and topology changes have negative evidence.
- Planned promotion fences source and waits for declared cut; unplanned promotion never silently claims zero RPO or proves remote death by timeout.

## Tasks

### M12.01: Create follower binding and scoped trust

Status: **planned**. Owner role: replication-module.

Goal: Bind one follower to one immutable source identity.

Depends on: M10.

Deliverables:

- Optional CCR crate, replication epochs, source export/destination import grants and read-only enforcement

Validation:

- Cross-tenant/role/mTLS denial, source name recreation and bulk/alias write bypass controls.

Definition of done:

- Follower public writes are rejected; source and destination membership are not merged.

### M12.02: Bootstrap snapshot with tail retention

Status: **planned**. Owner role: replication-module.

Goal: Avoid losing operations while initial snapshot transfers.

Depends on: M12.01.

Deliverables:

- Coordinated snapshot+stream lease, shared transfer/import reuse and atomic bootstrap checkpoint

Validation:

- GC between pin/lease registration, writes during copy, bootstrap restart and key rotation.

Definition of done:

- Follower starts streaming exactly after the captured source cut without gaps.

### M12.03: Implement durable stream apply and checkpoints

Status: **planned**. Owner role: replication-module.

Goal: Advance follower only after destination durability.

Depends on: M12.02.

Deliverables:

- Bounded pull batches, idempotent source/local map, schema-before-op and durable/applied/searchable status

Validation:

- Duplicate/out-of-order/gap/tampered operations; crash after durable import before reply; forced schema changes.

Definition of done:

- Different payload under one source identity stops replication; reported progress is contiguous and durable.

### M12.04: Implement retention, pause/resume and rebootstrap

Status: **planned**. Owner role: replication-module.

Goal: Bound lag cost and make expired history explicit.

Depends on: M12.03.

Deliverables:

- Lease byte/time caps, pause/stop/detach, expiry states and new-snapshot workflow

Validation:

- Long partition, slow follower, source disk pressure, expired lease and concurrent detach.

Definition of done:

- Default follower cannot retain unbounded source WAL or silently block all source tenants.

### M12.05: Replicate topology and compatibility transitions

Status: **planned**. Owner role: replication-module.

Goal: Follow source resharding and format evolution safely.

Depends on: M12.03, M13.03.

Deliverables:

Validation:

Definition of done:

### M12.06: Implement promotion and failback workflow

Status: **planned**. Owner role: replication-module.

Goal: Prevent accidental split brain and hidden RPO loss.

Depends on: M12.04, M12.05.

Deliverables:

- Planned fence/catch-up/activate protocol, explicit unplanned DR path and reverse migration runbook

Validation:

- Partition source while follower healthy; delayed old writer; destination writes before attempted rollback.

Definition of done:

- Planned promotion proves final cut; unplanned flow declares possible suffix loss and requires valid fencing/authorization.

### M12.07: Qualify CCR module and AI operations

Status: **planned**. Owner role: replication-module.

Goal: Prove end-to-end remote durability and diagnosis.

Depends on: M12.06, M08.

Deliverables:
