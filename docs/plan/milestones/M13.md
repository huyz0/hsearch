# M13: Catalog foundation, elasticity and fleet scaling

Generated from `tasks.json`; edit the ledger and run `python docs/plan/tools/plan.py render`.

Status: **planned**. Owner role: cluster/scale.

## Goal

Remove per-index resource floors and deliver safe hot-partition growth.

## Completion prerequisites

M07, M09, M10

Task-level dependencies determine when individual tasks can start. Milestone prerequisites gate completion.

## Definition of done

- Idle million-tenant catalog model has no per-idle-index worker/timer/group requirement and measured bounded enumeration/activation.
- Hot shards split/rebalance under writes with fenced routing transitions and preserved PIT/replication retention.
- Physical journal/query resources scale with active capacity, with skew/fairness/admission evidence.
- Idle/sparse/active/skewed tenancy, per-zone duplicate warmth and recovery traffic meet the selected profile cost envelope, not just a throughput target.

## Tasks

### M13.01: Implement paged catalog and cold activation budgets

Status: **planned**. Owner role: cluster/scale.

Goal: Make idle tenancy cheap and activation bounded.

Depends on: M03.05, M02.08, M05.01.

Deliverables:

- Catalog partition strategy, lazy engine lifecycle, active caps and footprint simulator

Validation:

- 1M tenants/50M-index model with >=99% idle, burst activation and catalog repair.

Definition of done:

- No O(total indexes) per-node polling/resource cost; model assumptions and real tested sizes are separate.
- Paged catalog/cold-activation mechanisms land before standalone/distributed API integration; later M13 tasks still own full elasticity/fleet proof.

### M13.02: Implement tenant fairness and hot placement

Status: **planned**. Owner role: cluster/scale.

Goal: Isolate cache/CPU/I/O and avoid hotspot collapse.

Depends on: M13.01.

Deliverables:

- Per-tenant admission, weighted placement, cache quotas, load feedback and bounded subscriptions

Validation:

- One hot tenant with many small tenants; cold cache storm, skew and AZ imbalance.

Definition of done:

- Tenant SLO interference and rejected work are measured; moving compute doesn't change authority.

### M13.03: Deliver online logical shard split and cutover

Status: **planned**. Owner role: cluster/scale.

Goal: Scale hot write partitions without ambiguous routing.

Depends on: M13.02, M10.

Deliverables:

- Snapshot/catch-up/split barriers, routing generation, fenced cutover and old topology pins

Validation:

Definition of done:

- Each document has one authoritative partition per routing generation; no loss/duplication and old views stay valid.

### M13.04: Qualify bounded physical group scaling

Status: **planned**. Owner role: cluster/scale.
