The collector runs pinned Rust production builds with `-C instrument-coverage -C link-dead-code`. Empty-profile maps from actual production objects define the denominator, including ordinary/unused generic code. Test-binary runtime maps contribute hits only to that denominator. Runtime-only tests/development sources are distinct from code compiled into production; an undeclared root/shared/development/external production map refuses instead of disappearing. Actual Cargo metadata, dependency/toolchain roots and bound build-script outputs constrain ownership. Declared source entries and owner metadata are rederived at merge.

Context version2 binds the complete accepted immutable source proof, actual head/base/source bytes, manifest owners, target/profile/features/flags, tool hashes/effective compiler, test inventory, production objects, exact binary shards and raw-profile records. Merge independently recomputes source proof at both ends, rehashes all physical inputs and refuses missing/stale/duplicate/extra artifacts. Changed lines are derived from verified proof only; a separate supplied list must match. Human patch text has no executable path. Each emitted profile summary also records the qualified base, context schema, source-proof digest and effective wrapper policy for actual hosted event verification. Source bytes and every line-oriented compiler/report protocol use LF framing; Unicode separators remain content.

All production aggregate/crate/file/changed-line floors remain>=90% in both dev and release. No executable lines means N/A with an exact-source reviewed audit, never100%. Missing instrumentation is an error. Ordinary tests keep the pinned nextest retries0/threads2/fail-on-timeout policy; explicit doctests, Clippy warnings/unsafe refusal and all applicable features remain separate required checks. Effective compiler/test environment overrides cannot silently weaken the policy. The runner pins the probed compiler and rustdoc, sets both compiler-wrapper environment variables to empty (disabling Cargo-configured wrappers), and refuses even an empty encoded-flags environment variable because it takes precedence over instrumentation flags. A byte-validated `harness/cargo-correctness.toml` policy forces compiler-child RUSTC_BOOTSTRAP=-1 through Cargo and nextest's Cargo invocations, overriding local forced bootstrap. Both collection and ordinary native checks execute the absolute attested cargo-nextest directly, retaining its required external-subcommand argv marker; Cargo aliases cannot select another runner. A hashed /usr/bin/env transparent executor, selected by the native target's highest-priority runner environment key, prevents Cargo target-runner configuration from replacing test execution. Compiler, rustdoc, nextest, executor and policy bindings are recorded in the context. The actual Cargo control first observes each configured nonexistent wrapper fail, then succeeds with the explicit disabled policy; toolchain context records those effective wrapper values. Cargo's target is explicitly pinned to the qualified native host, overriding build-target configuration. Ordinary native checks use a fresh exclusive policy-owned target directory, separate from earlier unqualified compiler outputs: Cargo does not fingerprint forced compiler-child bootstrap changes. Ordinary native checks retain their non-instrumented flags; collection retains its explicit instrumentation flags. These rules follow the [Cargo environment reference](https://doc.rust-lang.org/cargo/reference/environment-variables.html) and [flag precedence](https://doc.rust-lang.org/cargo/reference/config.html#buildrustflags). Both native targets remain required before acceptance.

## Base and event policy

A valid exact ancestor is required. An explicit `parentless-root` marker qualifies only an actually proven parentless root. CI's root event markers may normalize to that marker only after the immutable proof confirms the root; missing/nonancestor evidence on any ordinary history refuses. Impact uncertainty still chooses the full suite, but it cannot substitute all production lines as an unknown-base changed-percentage denominator. PRs use their real base, main pushes use the event's previous main, and manual dispatch requires `coverage_base`. Actual PR/main/manual event qualification is required; unit labels do not establish hosted event behavior.

```sh
python tools/coverage.py run --base <exact-ancestor-sha> --output /private/new-context
python tools/coverage_local.py --state-root /private/owned-leases --base <exact-ancestor-sha>
```

The local entrypoint freezes a clean source bundle, verifies host/Linux byte identity, runs both profiles in the existing owned non-root BUILD sandbox and retains bounded public evidence. It preserves TLS/storage isolation, BUILD/STORAGE caps and uncertain-outcome/owned cleanup rules. Host bundle capture uses the accepted bounded binary Git reader and admits at most128MiB before any bundle file creation, then writes exclusively. The admitted payload/join buffers use finite roughly256MiB payload storage plus bounded metadata, not a claim of a hard host RSS sandbox; pack thread/window/delta limits and its60s child deadline remain explicit. An oversized history refuses without writing a bundle file or rewriting history. Direct native CI also retains finite command argument/output/disk/deadline/thread guards and its job deadline; these flags alone are not a claim of a separate hard host memory sandbox. Artifacts preserve measurements/manifests, not dependency binaries or shared lease/TLS-key directories.
