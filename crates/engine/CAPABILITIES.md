## Boundary and lifetime

`Engine<'d>` borrows the caller's `Directory`; its `IndexWriter<'d>` cannot outlive that directory. The supported mode is one serial `IndexWriter` with a nonblocking adapter admission gate, the `Lucene104` codec, version 10.5.0, an 8 MiB RAM buffer, eight buffered documents and the frozen StandardAnalyzer profile. Independent private preparations and frozen readers may overlap. Competing apply/refresh/commit/merge admissions return `Busy`. A second native writer must fail its directory lock. ConcurrentIndexWriter, custom codecs, analyzers, writer configuration and remote inputs are not exposed.

The pinned source symbols are `IndexWriter::open`, `set_analyzer`, `set_ram_buffer_size_mb`, `set_max_buffered_docs`, `update_fields_documents`, `delete_documents_by_term`, `commit`, `force_merge`, and `set_commit_on_close`. `index_writer/lifecycle.rs:73` takes `self` in `close`; therefore adapter close consumes the adapter. `set_commit_on_close(false)` makes close roll back pending work. Native `DirectoryReader::open_from_writer` supplies NRT visibility; `DirectoryReader::open` opens committed files. Neither establishes hsearch authority, object/quorum durability, searchable receipts or archive state.

Use a trusted, exclusively owned, already materialized directory. The upstream `Directory::open` returns whole-file bytes and its default `file_length` also opens the file. This component does not make an arbitrary directory implementation, malformed native index, remote source or external concurrent modification safe. Bounded read-at/codec input validation and larger-than-cache qualification remain M02.03. There is no new persisted hsearch file format, WAL or authority protocol.

## Preparation, identity and errors

`Schema::new` requires a positive schema revision, 1..14 unique ASCII user field names (16 native fields including identity/version) of at most 64 bytes, and explicit single-valued required field types. Indexed names starting with `_` are reserved. `Mutation::Create` adds native create-only conflict refusal before effects. `Mutation::Put` replaces or creates, and `Mutation::Delete` retains a tombstone. Receipts retain Created/Updated/Deleted/NotFound outcomes on retries. `Snapshot::get` reads a logical identity at a frozen native snapshot; authoritative latest GET remains outside this component.

`Schema::prepare` accepts canonical schema order, stable nonempty caller IDs/requests of at most 256 UTF-8 bytes, positive caller versions, at most 16 distinct identities per batch, 8,192 bytes per document and 65,536 input bytes per batch. Integer values must fit int32, booleans must be typed booleans, and dates must be caller-parsed UTC milliseconds in years 0000..9999. Strings are never coerced. This typed representation does not preserve an original JSON spelling of a date or implement `strict_date_optional_time` parsing.

Preparation completes privately before admission. Invalid middle items cannot touch the writer; dropping a valid preparation represents caller refusal. `apply` is an explicit caller acceptance seam, not an authorization or consensus decision. It validates schema, exact retry payload, monotonic versions and all lifetime limits before the first native mutation. Repeated identities inside this component batch refuse. A future bulk facade must preserve independent semantic item receipts and repeated-ID order using separately resolved component calls; this batch is not the HTTP bulk contract.

Native documents store `_hs_id`, `_hs_version`, and every original typed field. Native internal document numbers never become logical identities. Request history retains exact canonical mutations and original ordered receipts, including missing deletes. A reused request with different payload refuses; a valid retry returns the old receipt without overwriting newer state. Tombstones retain versions. State is bounded to 128 identities, 128 physical documents between merges, 256 admitted lifetime operations and 262,144 history input bytes; no silent history eviction occurs.

`commit` returns an opaque caller-held in-process checkpoint only after native commit succeeds. Reopen requires that checkpoint, validates the latest in-process lineage epoch and native commit descriptor, and compares every live logical identity, version and stored payload, detecting duplicate IDs as well as altered data. Native descriptor fields are the existing SegmentInfos header id, generation and version (pinned segment_infos.rs:550); descriptor reads use existing read_latest at line727. The shared lineage lock serializes verification through native writer acquisition. Every successful commit advances the bounded checked epoch even when native identity or live documents are unchanged; old checkpoint clones cannot restore an earlier tombstone/request history. Native files alone cannot recover deleted-version/retry truth. The alternative is caller-resolved history replay into a fresh directory. Checkpoints are not serialized or advertised as crash-durable idempotency state.

Native apply, refresh, merge or commit errors can follow partial native effects. Continuation then refuses as `Poisoned`; existing snapshots remain readable. There is no rollback claim for a failed apply/commit. Native commit success followed by descriptor-read failure also poisons continuation and invalidates every checkpoint in the shared lineage. Close consumes the writer and attempts native rollback with commit-on-close disabled. A failed native close or implicit Engine drop leaves that lineage uncertain; recovery requires caller-resolved replay into a fresh directory. An explicit successful close after ordinary pending work permits reopening the last known checkpoint. Native writer fields drop before the lease that releases lineage admission. Failures are redacted enum values and never include native error strings or user payloads. A failed native close is returned; it is not retried or declared successful.
